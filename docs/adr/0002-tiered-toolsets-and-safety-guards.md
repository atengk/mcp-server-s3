# 0002. 分层工具套件矩阵、本地路径沙箱与递归删除三重防御体系

## 背景与决策 (Context & Decision)

对象存储操作维度广泛，涵盖从存储桶生命周期、目录层级模拟，到本地大文件传输与批量清理。当 LLM / AI 智能体拥有执行文件变更能力时，误操作（如传入空前缀清空全桶、读取 GB 级二进制大文件导致上下文撑爆、甚至读取宿主机敏感凭证上传至公网）将带来不可挽回的灾难。

我们决定采纳以下核心设计决策：
1. **五大专业套件全矩阵**：覆盖存储桶生命周期、检索探索、内容检视、双向流式传输及批处理与标签治理；
2. **全局只读门禁 (`Read-Only Guard`)**：通过 `MCP_S3_READ_ONLY=true` 在 MCP 握手协议层物理隐藏所有写/删类工具，杜绝模型幻觉产生写指令；
3. **工作区路径沙箱隔离 (`Sandbox Guard`)**：通过 `MCP_S3_ALLOWED_LOCAL_DIR` 严格将 `upload_file` 和 `download_file` 的本地磁盘访问限制在受管沙箱目录内，严禁 `../` 逃逸与非受管绝对路径访问；
4. **递归前缀删除三重防灾熔断 (`Prefix Deletion Guard`)**：强制禁止根前缀（空字符串或纯斜杠）、强制显式传递布尔确认参数（`confirm_recursive_delete: true`）、单批次强制截断上限为 1000 个对象；
5. **文本直读 256KB 智能截断器 (`Content Truncator`)**：限制 `read_object_text` 单次读取最大安全阈值，防止大日志或二进制文件撑爆 Agent 上下文窗口。

## 权衡考量 (Considered Options)

- **工具粒度与边界**：
  - 纯只读探索器：虽然安全，但 Agent 无法协助完成配置写入、日志归档或文件分发；
  - 无防护全功能：极易在生产发生删除事故；
  - 全功能 + 三位一体防御体系（已采纳）：兼顾了 100% 的日常运维生产力与绝对的数据安全防线。
- **本地文件读写安全**：
  - 允许读写宿主机任意路径：极其危险，可能导致 `~/.ssh/id_rsa` 被上传至公开 Bucket；
  - 工作区沙箱限制（已采纳）：保障 Agent 仅能在当前项目或指定数据工作区内操作磁盘。

## 后果与影响 (Consequences)

- 优势：
  - 19 项工具完整覆盖日常云存储运维全部高频场景；
  - 杜绝了由于 Agent 幻觉导致全桶数据被清空的风险；
  - 彻底规避了大文件直接吐给 LLM 造成的上下文风暴与费用超标。
- 代价：
  - 涉及递归前缀删除等高危操作时，Agent 需要显式传入确认参数。
