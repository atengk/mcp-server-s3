# 领域文档规范 (Domain Docs)

工程技能在探索与维护代码库时，遵循本仓库的领域文档规范。

## 探索代码库前必须阅读

- 根目录下的 **`CONTEXT.md`**（若存在）：记录全局通用领域语言与术语表。
- **`docs/adr/`**：记录架构决策记录 (ADR)。在涉及相关业务或技术边界时查阅。

> [!NOTE]
> 如果上述文件尚未存在，**请静默继续执行**，无需报错或主动提醒创建。当通过 `/domain-modeling` 明确了概念或落地了架构决策时，再按需延迟创建。

## 目录结构

单上下文工程布局（适用于本项目）：

```
/
├── CONTEXT.md          # 业务术语表与领域模型
├── docs/adr/           # 架构决策记录
│   └── 0001-*.md
└── src/                # 源码目录
```

## 术语使用准则

当输出物涉及领域概念时（包括工单标题、重构方案、假说推演、测试用例命名等），必须严格使用 `CONTEXT.md` 中定义的术语，杜绝随意自创近义词。

如果所需的领域概念在术语表中尚未收录，这表明要么使用了项目不采用的生造词（需重新评估），要么存在未定义的领域空白（需触发 `/domain-modeling` 补全）。

## 架构决策冲突审查

如果生成的方案或代码与现有 ADR 存在冲突，必须显式在回复中高亮提示，严禁静默覆盖：

> *与 ADR-0001 存在冲突 —— 建议重新讨论，原因是……*
